# Gate suite of the Pop III production prototype

Scripts: `scripts/proto/` (`gate.sh`, `tier_t{0..3}.sh`, `common.sh`, `compare_metrics.py`, `tol.json`, `states.txt`, `make_library.sh`, `config_grey.env`, `config_tdc.env`, `cases/`).
Purpose: every merge step into the prototype branch (`popiii-proto`) must pass the gate, and the numbers of Stage 1 (consolidation, grey production defaults)
are the reference of Stage 2 (TDC the only convection path, old MLT deleted).

## Configuration is a file, not code
`gate.sh --config FILE` (default `scripts/proto/config_grey.env`). The config is the KEY=VALUE word list given to `popiii_m2c.jl` (after the code's own
`popiii_stack.jl` defaults); the case file (`cases/z100.env` = zie1's mesh, `cases/z298.env` = zie3's) adds ENVEUL/ENVCORE; `gate.sh` adds only
per-job words (RESTART, MAXSTEPS, SNAPEVERY=5, NKCHECK, ...).
- **Stage 1** `config_grey.env`: `runs/zie1/run.env` deduplicated (last value of a repeated key wins, as `env` applies them; zie1 and zie3 differ only in the mesh),
  without mesh and SNAPEVERY. `phaseB.env` of zie1/zie3 is empty. It contains NKRYLOV=1, TITAN_NOLIB=1, TITAN_MGR=600; the TRTOL true-residual convergence is a code constant
  (`Trbdf2.TRTOL = 1`), nothing to set. No convection switch is set: production behaviour.
- **Stage 2** `config_tdc.env` is a PLACEHOLDER: the grey config plus `TDC=1 TDCPAR=... CONVDIAG=1` (what selects TDC in today's code). When Stage 2 is cut, delete the
  switch lines (they become unconditional) and use the Stage-1 T2/T3 metrics as `--ref` of the first Stage-2 run.
- `julia/TitanStack/src/envguard.jl` (branches prodpkg/pkgstart) lists the ~100 load-time ENV keys: a config key that is baked into a precompiled image must not differ between
  the gate and the reference run; check a new config against that list when the package branch is merged.

## Tiers
All tiers write `<out>/<tier>/metrics.json` (flat key -> number), `summary.txt`, `compare.txt`, and every job's own files. Jobs run on core slots
(`GATE_CORES`, default `120-127`; each slot = 8 cores, 8 threads; at most 4 slots used; fewer slots = serial). Checkpoints are COPIED into each run's directory, never written in place.

| tier | time | what |
|---|---|---|
| T0 | minutes | `t0_units.txt`: `julia/tdc_tests/{t4..t9,mesa_compare,t10_lresp}.jl` (PASS/FAIL lines counted AND the exit code and the final "failures: 0" line required: an exception fails the gate), plus `mg_test.jl` (MGRad group fractions/opacities, AD vs FD), `slabflux_test.jl`, `subzone_test.jl` (modules used by the stack, stand-alone, no libtitan). `popiii_regress.jl`: its snapshot files `lib/p2_runs/*_pure/snaps.jls` are regenerated by `phase6_run.jl pure SOD/SUBC/SUPC` in the sandbox (they do not exist in a worktree); SKIP with reason if that fails. `noh_test.jl`: SKIP with reason if TitanFortran cannot initialise. All run in a sandbox copy of `julia/` (the tests write logs under docs/ and TitanFortran creates lib/ dirs: the worktree stays clean). Not included: `t10_lresp_state.jl` (needs live modules), the Fortran-comparison checks (resid_check, fast_check, solver_check: need libtitan), h2*/nlte/nucnet tests (other physics, slow, not in the stack's hot path), infall_tests/order_test (long, scripted by name). |
| T1 | ~30 min | per library state (`states.txt`): **NKCHECK=2 grey and with MGROUPS=4** (`NWPROBE=<nwdt> NWPROBEAT=0 NKRYLOV=1 NKCHECK=2 NKZ=<a:b>`; falls back to iteration 1 for a state that converges before iteration 2, recorded as `.iteration`), parsed per equation (all zones and the NKZ zones: `nk.<state>.<grey|mg>.<eq>.<all|zones>`, plus global max/median/row counts, AD residual identity); **ETOTMON ledger** over `GATE_ETOT_STEPS` (40) steps (`etot.<state>.imb_over_thr` = sum|imb|/sum thr, max/median |G|); **checkpoint round trip** (continue 15 steps writing a checkpoint at k0+5 via CKDUMP, restart from it for 10 steps, every field of the snapshots at steps > k0+5 `isequal` to the continuous run: `t1.roundtrip.<state>.fields_diff`); **bit-identity** of the IC start (MGROUPS off, 40 steps, `GATE_BITCASE`, all fields of all snapshots) between this tree and `--bitref` (a worktree directory or a commit, checked out detached under the output dir and removed afterwards; first use: `--bitref prodpkg` to show the prototype reproduces production). |
| T2 | 1-2 h | `GATE_PILOT_STEPS` (200) steps from each library state, one slot each (CONVDIAG=1, NWTRACE, ETOTLOG): Newton-failure rejections, error rejections, Newton iterations (mean/median/max, >10), min/median snapshot dt, simulated time, wall s/step (slope of perf.csv), F_c/F_tot, P_t/P (TDC only), R*, Mdot, energy ledger. `pilot.<state>.*` |
| T3 | nightly | from the IC to M* >= `GATE_MSTOP` (34 Msun) at z100 and z298 on two slots, segments of `GATE_SEG` (400) steps each restarting the previous segment's checkpoint, resumable (`procedure.log`; rerun the same command with the same `--out`). Then `m4extra.jl` export and `t3_metrics.py`: observables at fixed M* (1, 3, 10, 30) and their relative difference to the production export (`--ref-export [case=]DIR`; default `subconv/m4/exports/B0` for z100 and `B0z3` for z298, smin 290 / 775), the `m4compare.py` tables in `t3/compare_<case>.txt`. `t3.<case>.*` |

`gate.sh all` = T0 + T1 + T2 (T3 is the nightly run). Exit status 1 if any FAIL.

## Running
```
export JLENV=/zpool/nvme/data/tabel_scratch/titan_popiii/subconv/jlenv     # default
scripts/proto/gate.sh T0 --out $DATA/proto/gate/mystep
scripts/proto/gate.sh T1 --bitref prodpkg --cores "120-127 112-119 104-111 96-103"
scripts/proto/gate.sh T2 --ref $DATA/proto/gate/stage1_ref/t2/metrics.json
scripts/proto/gate.sh T3 --out $DATA/proto/gate/nightly --ref-export z100=/path/to/export
CODE=<prototype worktree> scripts/proto/make_library.sh      # once: the prototype's own checkpoint library
```
GPU is not used. Pin to free cores (the box is shared); `GATE_STATES=k295,k655` restricts the states. Do not point `--out` into `runs/*` or `subconv/m4/*`.

## References and updating them
`metrics.json` of a tier is the reference: store `<out>/tN/metrics.json` under `$DATA/proto/gate/ref/<name>/tN/metrics.json` together with the code commit, config and library
it came from (a one-line `README` next to it). `--ref DIR` takes the directory (all tiers) or a single `metrics.json`. Update a reference only deliberately:
(1) the change that moves the numbers is understood and documented, (2) re-run the tier twice (T2 wall numbers are noisy on the shared box), (3) copy. At the Stage 1 -> 2 cut the
Stage-1 T2/T3 metrics become the references and Stage 2 gets its own `tol.json` bounds where physics is intended to change (convection rows: `nk.*.grey.w.*` and F_c, P_t keys).

`compare_metrics.py new.json ref.json tol.json` prints PASS/WARN/FAIL per key; first matching rule of `tol.json` wins. Modes: `upper`/`lower`/`absupper`/`zero` (absolute, no reference needed),
`rel` (|new-ref| against a fraction of ref, WARN above half the tolerance), `rise` (only an increase counts), `info`.

## Tolerances and why
- Unit tests, round trip, bit-identity: zero failures, zero differing fields (exact, no tolerance).
- NKCHECK rows <= 1e-5 (the documented FD noise floor, eps = 1e-5: 3e-6 .. 5e-6 in the post-shock zones, POPIII_CONVECTION M3b.3b), AD residual identity <= 1e-12 (documented 5e-18). **Known-noisy rows listed explicitly** with the documented values: F_r <= 1 (closure rows, 5e-2 .. 17), E_r <= 1e-3 (9.1e-4), x_H+ / z_H <= 1e-2 (2.5e-3), x_H2 <= 2e-3 (iteration 2: 3.8e-4 at k295 in the smoke test; 4e-6 at iteration 1), T over all zones <= 5e-2 (zone 1: 1.7e-2, 2.6e-2), MGROUPS=4: group rows <= 1e-4 (E_g 2.7e-5), F_g1/F_g4 <= 1e-3 (1.9e-4), F_g2/F_g3 <= 1e5 (mgprod noise rows 0.12 .. 4e4: effectively info), w rows info in grey (FB-kink rows are not FD-testable). Counts of rows above 1e-4 / 1e-2: +50 % with a floor.
- Energy ledger: |sum imb|/sum thr <= 1e-2 (the stack's own 4e-3 .. 9.8e-3; WARN above 8e-3), max |G| <= 5e-2 (documented 1e-2).
- Newton-failure and error rejections: +50 % (floor +3): the 200-step counts at the pilot states are 12-33, statistical scatter between code versions is several; wall s/step +30 % (WARN +15 %; shared box noise).
- Physics observables (T2 snapshots, relative to the reference): simulated time 15 %, median dt 30 %, min dt 50 % (spiky), F_c/F_tot 15 % (+0.05), P_t/P 30 %, R* 30 % (one mesh zone is 29 %), Mdot 5 %.
- T3 against production (relative difference at fixed M*; bounds from the M4 spreads, docs/POPIII_CONVECTION.md M4): Mdot(1e4 Rsun) 2 % (spread <= 0.36 %), u_min 15 % (<= 13 %), Mdot_shock 12 % (4-10 %), s_ps 8 % (<= 6 %), T_c 7 % (2-5 %), R* 35 % (zone), Teff/L_ph 25/30 %.
These are initial values chosen from the documented noise of the subconv work, not from the prototype; tighten them after the first Stage-1 runs.

## Default merge gate (agreed with the multigroup session, 24 Nov 2026)

Every merge into `popiii-proto` must pass these five gates. Everything else in T0–T3 runs on demand or nightly.

1. **NKCHECK=2** (AD vs FD J·v), grey **and** `MGROUPS=4`, on the fixed state set.
   - The set includes the zie1 ionisation-front checkpoint (front zones 44–47).
   - References: grey 1.5e-10 (cc7b8dc zie1: 1.64e-10); MG 2.306e-7 (mgprod 063452c).
   - FAIL if either worsens.
2. **Bit-identity with `MGROUPS` unset** against the previous gated commit: step lines plus decompressed tstate.
   - Exception: a deliberate physics change (e.g. Stage 2: TDC as the convection path). It is gated by gates 1, 3, 4 and 5 against the previous metrics (gate 5: steps accepted and median dt vs Stage 1, because TDC changes the energy row MG also uses) and recorded as a new reference.
3. **Late production restarts**: 50 steps each, from copies of zie1 S16 and zie3 S8 (`/zpool/nvme/data/tabel_scratch/titan_popiii/prod_env/`; never `runs/zie*`).
4. **ETOTMON** over a fixed window: it must close no worse than at the previous gated commit.
5. **One MG window**: zie3 from fp3a1, 40 steps. At 063452c all steps are accepted, with a median dt of about 9e3 s.
   - When mgstart lands, add MG from the IC, 100 steps.

**Not in the default suite** (inert unless switched on; the code stays): SWDIAG, EIGDIAG, the DTERRDIAG group extension, the h2diag tables, photoheat_check.jl.

**Speed:** run the suite with `TITAN_PKG=1` against one image built per gated commit. Time to first step falls from about 400 s to about 95 s per run (measured on the production restarts by the MG session).
